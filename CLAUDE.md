# Infeara — Claude & ChatGPT Project Guide

This repo contains 36 Infeara skills (see `skills/README.md` for the catalog), shipped as Claude skills and as a ChatGPT/Codex plugin.

## Where things live

- Canonical skills: `skills/<skill-name>/SKILL.md`
- Claude Code mirror (auto-discovered): `.claude/skills/<skill-name>/SKILL.md`
- Claude plugin at the repo root: `.claude-plugin/plugin.json` + `icon.png` (this is what a repo ZIP upload reads)
- Claude Code marketplace: `.claude-plugin/marketplace.json`
- ChatGPT/Codex plugin: `plugins/infeara/`
- ChatGPT/Codex plugin package: `plugins/infeara/` (`plugin.json`, `assets/`, `skills/`)
- Plugin icons: `plugins/infeara/assets/logo.png` (1024²), `composer-icon.png` (512²)

Edit `skills/` only, then re-sync:

```bash
cp -r skills/infeara-* .claude/skills/
./scripts/build-plugin.sh      # also validates and rebuilds dist/infeara-plugin-<version>.zip
```

Never edit `plugins/infeara/skills/` by hand — it is generated by `scripts/build-plugin.sh`.

## Plugin rules

1. `plugins/infeara/chatgpt-plugin.json` is the portable Agent Plugins manifest (renamed so the repo keeps exactly one `plugin.json`); OpenAI listing metadata lives under `extensions.com.openai`.
2. Listing limits: `displayName` ≤ 30, `shortDescription` ≤ 30, `longDescription` ≤ 4000, `developerName` ≤ 80, ≤ 3 `defaultPrompt` entries of ≤ 128 chars, `category` from the directory list.
3. Icons must be square, PNG/JPEG/WebP/SVG, ≥ 48 px (logo ≥ 512 px), ≤ 5 MiB, referenced with `./`-prefixed paths.
4. No MCP server: this is a skills-only plugin, so no `mcp.json`, no review test cases, no demo recording.
5. Never invent listing URLs — `websiteURL`, `supportURL`, `privacyPolicyURL`, `termsOfServiceURL` stay unset until real pages exist.
6. Run `python3 scripts/validate-plugin.py` and `claude plugin validate plugins/infeara` before any submission.

## Conventions for Claude in this repo

1. Load the single best-matching skill; chain others only when the task spans domains (e.g. a sales proposal needs Sales + CFO + Legal).
2. Follow each skill's Quality Checklist before delivering.
3. Respect each skill's Guardrails — never invent financials, client facts, evidence, or legal advice.
4. When editing skills, keep frontmatter `name` identical to the folder name and keep `description` trigger-rich (include "Use when…" phrases).
5. Keep each `SKILL.md` under ~120 lines — concise enough to load without bloating context.
6. `infeara-document-writer` ships non-markdown assets (`references/*.html`, `assets/*.png`); `scripts/build-plugin.sh` copies the whole folder, and `validate-plugin.py` fails if a referenced file is missing.
7. When adding or removing a skill, update `skills/README.md`, `CLAUDE.md`'s routing table, and `plugins/infeara/skills/get-started/SKILL.md` together, then rebuild.
